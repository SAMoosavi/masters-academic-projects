# A Lightweight CLAS without Pairing for VANETs

## Overview

This paper identifies a temporary rogue key vulnerability in Zheng et al.'s CLAS scheme: an adversary can exploit random numbers in signatures to generate an ephemeral rogue key, enabling aggregate signature forgery using both the rogue key and the adversary's private key. The forged signature passes verification undetected.

The fix incorporates an additional aggregator's signature into the original framework, implementing simultaneous verification of both the aggregator's signature and the aggregate signature to resist rogue key attacks. Performance evaluation demonstrates significant advantages in computational efficiency and communication cost.

## Relevance to Our Work

The rogue key attack is a novel attack vector not covered by standard Type I/II/III taxonomy. Our scheme must be analyzed against this attack. The aggregator signature technique is a potential countermeasure we can adopt.

## Key Contributions

- Identifies temporary rogue key vulnerability in Zheng et al.'s scheme
- Proposes aggregator's signature as countermeasure
- Simultaneous verification of aggregator + aggregate signatures
- Lightweight construction with security advantages

## Mathematical Notation

**Rogue key attack on Zheng et al.:**
- Adversary generates ephemeral rogue key: $PK_{rogue} = \Delta P$
- Uses random numbers in signatures to create valid-looking forgery
- Forged aggregate passes verification

**Countermeasure (aggregator signature):**
- Aggregator signs the aggregation: $\sigma_{agg\_sign} = r_{agg} + h_{agg}(x_{agg} + D_{agg}) \mod q$
- Verification checks both: $\sigma_{agg}$ AND $\sigma_{agg\_sign}$ simultaneously

## Protocol / Scheme

1. **Setup**: System parameters
2. **KeyGen**: Standard CLAS key generation
3. **Sign**: Vehicle signs message
4. **Aggregate**: Aggregator combines signatures AND adds own signature
5. **Verify**: Simultaneous verification of aggregate + aggregator signature
