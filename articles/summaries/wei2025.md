# A New Efficient and Provably Secure CLS Without Bilinear Pairings for IoT

## Overview

This paper is an IoT-CLS scheme — not a VANET scheme, not an aggregate (CLAS) scheme, but a single certificateless signature (CLS) scheme for the Internet of Things (p.1, Title; p.1, Abstract).

It demonstrates that many pairing-free CLS (PF-CLS) schemes share the same vulnerability to forged signature attacks, and uses a novel Common Factor Substitution Attack to prove that a class of PF-CLS schemes cannot resist Type I adversary attacks even after prior improvements blocking older attacks (p.1, Highlights; p.3, §1.2; p.8, Definition 1). The authors then introduce an enhanced pairing-free scheme that binds both parts of the user public key to the system public key via a hash, proven resilient against both Type I and Type II adversaries under the random oracle model (ROM), with higher computational efficiency than compared PF-CLS schemes (p.1, Highlights; p.3, §1.2; p.8, §5).

## Relevance to Our Work

Scope is IoT-CLS, not VANET and not aggregate — single CLS only (p.1, Title; p.1, Abstract). Its attack methodology is still relevant as a cautionary analogue: it shows many claimed-secure pairing-free schemes share a common vulnerability class to public-key-replacement forgeries (p.7–8, §4). Our CLAS-for-VANET audit must test the same forgery class (Type I replacement with a common factor) against aggregate verification, which this IoT-CLS paper does not cover (p.8, Definition 1; p.13, §8).

## Problem

IoT traffic runs over the open Internet exposed to eavesdropping, tampering, and forgery, so lightweight authentication is paramount (p.2, §1).
Certificate management (store, distribute, verify, revoke) is too heavy for IoT, while IBC escrows full private keys to the PKG, motivating certificateless keys where the KGC issues only a partial key (p.2, §1).
Prior pairing-free CLS repairs keep falling in turn — He to Type II, Gong to Type I, then Wang–Yeh–Jia–Du–Xiang–Ma–Feng chains each broken again (p.2–3, §1.1).
A shared vulnerability class persists: even fixes blocking older forgeries still admit a new common-factor forgery by Type I adversaries (p.1, Highlights; p.3, §1.2).
Scope here is single-signer IoT-CLS only, not aggregate and not VANET (p.1, Title; p.1, Abstract).

## Method

Review four PF-CLS schemes (Xiang, Du, Karati, Pakniat–Vanda) over six algorithms from Setup to Verification (p.4–6, §3).
Define the Common Factor Substitution Attack: independent randoms scaled by a common factor so replaced keys and signatures still verify (p.8, Definition 1).
Break Xiang/Du via forged keys scaled by the system key with a matching forged scalar passing verification for any message (p.7, §4.1).
Harden Pakniat–Vanda with h1 over Q_ID to block Shim's forgery, then break the hardened variant with the same common-factor attack (p.7–8, §4.2).
Break Karati by the same attack, by direct reference to the above forgery flow (p.8, §4.2).
Propose an enhanced scheme binding both key parts to P_pub via H1(ID, X_ID, R_ID, P_pub), with Schnorr-style signing and single-equation verification (p.8, §5).
Prove EUF-CMA security against super Type I and Type II adversaries in ROM under ECDLP via the forking lemma (Theorems 1–2) (p.9–11, §6).
Benchmark sign/verify time and signature size against six comparators on MIRACL over 1000 runs (p.11–12, §7).

## Key findings

- The common-factor forgery passes verification for any user on any message in all four schemes, including the Shim-hardened Pakniat–Vanda variant (p.7–8, §4.1–4.2).
- The vulnerability class is structural: forged components share no relation the verifier can check, so prior per-scheme patches do not remove it (p.8, Definition 1).
- The enhanced scheme resists both super Type I and super Type II forgeries in ROM under ECDLP (Theorems 1–2) (p.9–11, §6).
- Verification costs 3Tsm + 3Tpa = 1.008945 ms, below Feng/Ma at 1.343218 ms and Du/Xiang at 1.341176 ms, with total cost about 19.76–20.05% below Feng/Ma, Du/Xiang, and Pakniat (p.12, §7; p.12, Table 2).
- Signature size is |G| + |Z_q*| = 480 bits, half the communication of Pakniat's 840-bit signatures (p.12, §7; p.12, Table 2).

## Key Contributions

- Introduces the Common Factor Substitution Attack, where forged X*, R*, T* are generated from independent randoms scaled by a common factor so the verifier cannot detect public-key forgery (p.8, Definition 1).
- Proves four PF-CLS schemes (Xiang et al., Du et al., Karati et al., Pakniat–Vanda) cannot resist Type I adversary forgeries, including an improved Pakniat–Vanda variant hardened against Shim's attack which still falls to the new attack (p.7–8, §4.1–4.2).
- Proposes a new pairing-free CLS binding both public-key parts X_ID and R_ID to P_pub via H1(ID, X_ID, R_ID, P_pub), avoiding Ma et al.'s independent-generation Type II weakness (p.3, §1.2; p.8, §5).
- Proves EUF-CMA security against super Type I and Type II adversaries in ROM under ECDLP via forking-lemma reductions (Theorems 1–2) (p.9–11, §6).
- Reports lower total computation than six comparators, with verification 3Tsm + 3Tpa = 1.008945 ms and signature size |G| + |Z_q*| = 480 bits (p.12, Table 2; p.12, §7).

## Mathematical Notation

### Setup

$$
\begin{aligned}
&s \leftarrow \mathbb{Z}_q^*,\quad P_{pub} = sP \\
&H_1 : \{0,1\}^* \times \mathbb{G}^3 \rightarrow \mathbb{Z}_q^*,\quad H_2 : \{0,1\}^{*2} \times \mathbb{G}^3 \rightarrow \mathbb{Z}_q^*
\end{aligned}
$$

KGC selects elliptic-curve additive group G of order q with generator P, master key s, public key P_pub = sP, and publishes params = (G, q, P, P_pub, H1, H2) (p.8, §5).

### Set Secret Value

$$
\begin{aligned}
&x_{ID} \leftarrow \mathbb{Z}_q^* \\
&X_{ID} = x_{ID}P
\end{aligned}
$$

User picks secret x_ID and computes X_ID = x_ID·P, transmitting it to KGC (p.8, §5).

### Partial Private Key Extract

$$
\begin{aligned}
&r_{ID} \leftarrow \mathbb{Z}_q^*,\quad R_{ID} = r_{ID}P \\
&h_1 = H_1(ID, X_{ID}, R_{ID}, P_{pub}) \\
&d_{ID} = r_{ID} + h_1 \cdot s
\end{aligned}
$$

KGC picks r_ID, computes R_ID = r_ID·P, h1 = H1(ID, X_ID, R_ID, P_pub), partial key d_ID = r_ID + h1·s, and sends (d_ID, R_ID) over a secure channel (p.8, §5).

### Set Private/Public Key

$$
\begin{aligned}
&SK_{ID} = (x_{ID}, d_{ID}) \\
&PK_{ID} = (X_{ID}, R_{ID})
\end{aligned}
$$

Full private key SK_ID = (x_ID, d_ID) and public key PK_ID = (X_ID, R_ID) (p.8, §5).

### Signature

$$
\begin{aligned}
&t \leftarrow \mathbb{Z}_q^*,\quad T = tP \\
&h_2 = H_2(m, ID, X_{ID}, R_{ID}, T) \\
&v = t + h_2(x_{ID} + d_{ID}) \bmod q \\
&\tau = (T, v)
\end{aligned}
$$

Signer picks t, computes T = tP, h2 = H2(m, ID, X_ID, R_ID, T), v = t + h2·(x_ID + d_ID), outputting τ = (T, v) (p.8, §5).

### Verification

$$
\begin{aligned}
&h_1 = H_1(ID, X_{ID}, R_{ID}, P_{pub}) \\
&h_2 = H_2(m, ID, X_{ID}, R_{ID}, T) \\
&vP \stackrel{?}{=} T + h_2(X_{ID} + R_{ID} + h_1 \cdot P_{pub})
\end{aligned}
$$

Verifier recomputes h1, h2 and accepts iff vP = T + h2·(X_ID + R_ID + h1·P_pub) (p.8, §5).

Pairing-free construction uses only ECC scalar multiplication, point addition, modular arithmetic, and general hashes — no bilinear-pairing operator appears anywhere in the scheme or summary equations (p.8, §5; p.11–12, Tables 1–2).

## Protocol / Scheme

1. **Attack demonstration**: Common Factor Substitution Attack forges X*_ID = x*·P_pub, R*_ID = r*·P_pub, T* = t*·P_pub and τ* satisfying τ*·X*_ID = h2*·T* + h3*·(R*_ID + h1*·P_pub), passing verification for any message (p.7, §4.1).
2. **Hardened-variant break**: improved Pakniat–Vanda with h1 = H1(ID, R_ID, P, Q_ID, P_pub1) blocks Shim's Q*-forgery yet still falls to the same common-factor attack with X* = x*·P_pub1, R* = r*·P_pub1, Q* = q*·P_pub1 (p.7–8, §4.2).
3. **Enhanced signing and verification**: binds X_ID and R_ID to P_pub via H1 and verifies vP = T + h2·(X_ID + R_ID + h1·P_pub), resisting both Type I and II attacks (p.8, §5).

## Security Analysis

- Type I adversary replaces the public key without the master key; Type II holds the master key but cannot replace the public key, formalized as Games 1–2 with CreateUser, ReplacePublicKey, ExtractSecretValue, ExtractPartialPrivateKey, and SuperSign oracles (p.3–4, §2.2).
- Enhanced scheme is EUF-CMA against super Type I (Theorem 1, advantage ≥ (1 − 1/q_H1)^q_eppk · (1/q_H1) · ε) and Type II (Theorem 2, similar bound) in ROM under ECDLP hardness via the forking lemma (p.9–11, §6).
- Security rests on the elliptic-curve discrete logarithm problem: given Q = aP, no PPT algorithm finds a with non-negligible probability (p.3, §2.1).

## Performance

- Measured on MIRACL with Intel i5-3470 @ 3.20 GHz, 4 GB, Ubuntu 22.04.3, 512-bit p / 160-bit q curve matching 1024-bit RSA security; Tsm = 0.334273 ms, Tpa = 0.002042 ms averaged over 1000 runs (p.11, §7; p.11, Table 1).
- Signing costs Tsm; verification costs 3Tsm + 3Tpa = 1.008945 ms, below Feng/Ma (4Tsm + 3Tpa = 1.343218 ms) and Du/Xiang (4Tsm + 2Tpa = 1.341176 ms) (p.12, §7; p.12, Table 2).
- Total cost is ~19.76% below Feng/Ma, ~19.80% below Du/Xiang, ~20.05% below Pakniat, and slightly below Karati; signature size |G| + |Z_q*| = 480 bits versus Pakniat's 2|G| + |Z_q*| = 840 bits (p.12, §7; p.12, Table 2).
- Pairing-free construction targets resource-constrained IoT computation and communication limits (p.11–12, §7).

## Strengths & Limitations

- Strength: identifies a shared vulnerability class across published PF-CLS schemes and gives a reusable attack template beyond one-off cryptanalysis (p.7–8, §4).
- Strength: proposed fix is minimal (hash-binding both key parts) while preserving single-scalar-mult signing and 480-bit signatures (p.8, §5; p.12, Table 2).
- Limitation: single CLS only — no aggregation, batch verification, pseudonyms, traceability, or VANET mobility handling, so VANET transfer needs separate work (p.8, §5; p.13, §8).
- Limitation: evaluation is computation-only on one desktop CPU with no IoT-device deployment or side-channel (timing/power) measurement, listed as future work alongside ZKP/ring-signature anonymity (p.13, §8).
